activity启动和service启动

Posted on 2017-02-24

Activity 和 Service 是 Android 里最重要的两个核心组件，平时研究得也比较多。

startService 和 bindService 的区别

  • startService() 启动：Service 接收 Intent，经历 onCreate() 和 onStartCommand()；调用方发出停止意图后，走 onDestroy()。
  • bindService() 启动：和 Activity 绑定时，经历 onCreate() 和 onBind()；Activity 被销毁时，先走 onUnbind()，再走 onDestroy()。
  • 用 startService 启动的服务和调用者没有关联，即使调用者退出了，服务仍然在运行。
  • 用 bindService 启动的服务和调用者绑在一起，调用者一旦退出，服务也就终止了。

Binder

Android 需要建立一套新的 IPC 机制，来满足系统对通信方式、传输性能和安全性的要求，这就是 Binder。这篇文章可以反复阅读。

Binder 通信里有四个角色：

  • Client 进程：使用服务的进程。
  • Server 进程：提供服务的进程。
  • ServiceManager 进程：把字符形式的 Binder 名字转换成 Client 中对该 Binder 的引用，让 Client 可以通过名字拿到 Server 中 Binder 实体的引用。
  • Binder 驱动：负责进程之间 Binder 通信的建立、Binder 在进程之间的传递、引用计数管理，以及数据包在进程之间的传递和交互等一系列底层支持。

启动流程

那它们的启动流程到底是怎么样的？看到一篇非常好的文章：Activity 启动流程，我就不献丑了。

基本流程涉及两个 IPC：应用进程和 system_server 进程。应用进程里涉及的线程包括 UI 线程和 ApplicationThread。

Service 和 Activity 的流程基本差不多。这里介绍几个关键的类：

  • ActivityManagerService（一般简称 AMS，类似的重要服务还有 PackageManagerService、WindowManagerService）：相当于 BookManagerService，是服务端。服务端提供哪些接口，就相当于 IBookManager 里声明了哪些方法。
  • ActivityManagerNative：怎么和服务端通信？需要一个 AIDL 接口，它就相当于 IBookManager.Stub。
  • ActivityManagerProxy：具体方法的实现就在这里，Proxy 才是真正干活的。
  • Instrumentation：工具类。

AIDL 的具体实现可以看这篇。

关于 AMS，它虽然叫 Activity 管理服务，但实际上 Service 也在它里面管理。

启动 Activity 至少需要两个前提：第一，应用进程存在；第二，AMS 已经初始化完毕。
