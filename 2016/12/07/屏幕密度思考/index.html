屏幕密度思考

Posted on 2016-12-07

像素密度以及不同屏幕

这是 Android 开发和设计都很关心的问题，我们就从 Material Design 的文档里学一下。

几个概念

  • Pixel density（像素密度）：每 inch 上的像素数。
  • Screen resolution（屏幕分辨率）：屏幕上总共的像素数。
  • 屏幕密度 dpi：也就是像素密度。为简便起见，Android 把所有屏幕密度分成六种通用密度：低、中、高、超高、超超高、超超超高。
  • Density-independent pixels（密度无关像素，dp）：A dp is equal to one physical pixel on a screen with a density of 160. 也就是说在 160dpi 的屏幕上，1dp = 1px，换算公式是 px = dp * (dpi / 160)。

通用尺寸和通用密度

为了简化多屏幕适配，Android 把实际屏幕尺寸和密度的范围分成 4 种通用尺寸（小、正常、大、超大）和 6 种通用密度：

密度 名称 参考 dpi
ldpi 低 ~120dpi
mdpi 中 ~160dpi
hdpi 高 ~240dpi
xhdpi 超高 ~320dpi
xxhdpi 超超高 ~480dpi
xxxhdpi 超超超高 ~640dpi

所以在 160dpi 的屏幕上 1px = 1dp，同理在 320dpi 的屏幕上 2px = 1dp。

六种通用密度对应哪些分辨率

通用尺寸和密度是按基线配置（正常尺寸 + mdpi）排列的，所以依次是超大对应超高……但实际生活中，每种通用尺寸和密度都涵盖一个实际的范围。比如两部都报告正常屏幕尺寸的设备，手动测量时实际尺寸和高宽比可能略有不同；两台报告 hdpi 的设备，实际像素密度也可能有差异。实际开发中，这种差异可以忽略。

为不同屏幕尺寸设计 UI 时，每种设计都需要一个最小空间。所以每种通用屏幕尺寸都关联了系统定义的最低分辨率，这些最小尺寸用 dp 表示——布局里也用同样的单位，系统就不用操心屏幕密度的变化。

  • 超大屏幕：至少 960dp x 720dp，设计建议 1280 x 720
  • 大屏幕：至少 640dp x 480dp，设计建议 800 x 480
  • 正常屏幕：至少 470dp x 320dp，设计建议 480 x 320
  • 小屏幕：至少 426dp x 320dp，设计建议 320 x 240

基准该定在哪一档

设计师的资源也有限。当时市场上 xxhdpi 手机越来越多，ldpi 和 mdpi 基本已经退出市场，兼顾各种 dpi 考虑下来，应该把 320dpi 作为基准。（一年之后基准可能就要调到 xhdpi，换机速度太快，设计的时候可以去统计网站看看当前市场上的分辨率分布。）

xhdpi 向上向下都能兼容，比例不会变得很离谱。你想想，如果在 mdpi 上设计的很完美的图，放到 xxhdpi 上可能已经小得不像话了，只有原来的 1/3，所以也不能拿 xxhdpi 当标准。

有个问题要提醒设计师：160:240:320:480:640 = 2:3:4:6:8，中间有个 3:4。以 xhdpi 为基准时，设计的像素值最好是 4 的倍数，否则在 hdpi 上容易出现小数点的像素，造成 UI 变形。实在做不到，那也只能开发这边四舍五入了。

设计和开发无需为屏幕尺寸和密度的每个组合都提供备用资源。系统提供了强大的兼容性，可以处理在任何设备屏幕上渲染应用的大部分工作，前提是您已经使用了可以适当调整大小的技术来实现 UI。
